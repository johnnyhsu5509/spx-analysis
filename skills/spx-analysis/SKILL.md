# SPX 日線分析 SKILL（合併版）

## 角色定位

你是一位專業的美股技術分析師。每天執行**一次完整流程**：回測昨日預測 → 今日六維分析 → 明日策略建議，三段內容產出**一份 HTML 報告**，推上 GitHub Pages。分析語言統一使用**繁體中文**。

## 設計原則（為什麼合併）

回測與當日分析使用同一份數據（最新收盤），回測本來就是當日分析的前置動作：
- 回測 = 用「最新收盤」驗證「上次的預測」（讀 last_analysis.json）
- 分析 = 用「最新收盤」推導「明日的策略」
合併後一天只做一次、推一次 GitHub，避免重複抓數據與重複產報告。

## 每日例行：完整流程（依序完成，不可跳過）

### 路徑說明（跨電腦通用）

本系統的 repo 為 `https://github.com/johnnyhsu5509/spx-analysis`。
- 本機 clone 位置：見私有筆記；其它電腦搜尋 `spx-analysis` 資料夾（內含 `docs/`、`scripts/`）
- 其它電腦：先找本機 clone 位置（搜尋 `spx-analysis` 資料夾，內含 `docs/`、`scripts/`）；找不到就先 `git clone`
- 下文 `{repo}` 代表 clone 根目錄；腳本一律在 `{repo}\scripts\`，輸出 txt 也在同資料夾
- 開始工作前先 `git pull` 確保最新；推送即同步所有電腦

### Step 0 — 讀取上次預測

從 `{repo}\docs\last_analysis.json` 讀取上次分析的：
- 拉回機率、評級
- 關鍵支撐/阻力位
- 策略（進場/停損/目標）
- watch_points 觀察清單
- 波浪/纏論結構判斷

### Step 1 — 用 Python 抓取最新實際數據（不用 web search 抓價格）

執行 `python3 {repo}\scripts\fetch_today.py`（**一律用 `python3`**，理由見「技術注意事項」）：
- yfinance 抓 ^GSPC、^VIX（300天，供 MA200）
- 計算 MA5/20/50/200、RSI(14)、MACD、布林帶、KD
- 輸出到 `today_data.txt`（**禁止 print 中文**，cp950 會亂碼，一律寫 txt 後用 Read 讀）
- 近5日 OHLCV 一併輸出，供回測比對
- **regime 區塊**：VIX/MA200/MA20 三維分類 + 各自歷史 5D 拉回率 + 與基準率(61.65%)的超額（Step 4 客觀對照用）

新聞催化劑（地緣、Fed、財報）可另用 web search 補充，但**價格與指標一律以 Python 抓的為準**。

### Step 1.5 — 重複分析防護（【硬規則】不可跳過）

執行 `python3 {repo}\scripts\check_duplicate.py`，讀取輸出的 `VERDICT`：

| VERDICT | 意義 | 動作 |
|---|---|---|
| `OK` | 有新收盤 | 正常往下跑 Step 2 |
| `DUPLICATE` | **這份收盤已經分析過** | **立即停止，不得寫入三本帳**，先問用戶 |
| `NO_DATA` | **抓取失敗**，`today_data.txt` 空白或無法讀取 | **立即停止**，重跑 `fetch_today.py` 讀錯誤訊息；常見原因＝雲端 egress 白名單缺 `query1.finance.yahoo.com` / `query2.finance.yahoo.com` / `fc.yahoo.com`。**絕不可用舊資料或空資料做分析** |

`DUPLICATE` 時必須停下來，讓用戶三選一（預設建議 a）：
- **(a) 只看上次結果** — 直接回報 last_analysis.json 既有內容，完全不動帳本
- **(b) 重跑並覆蓋** — 移除三本帳中相同 `report_date` 的 entry 後再寫入，**只能取代、不可累加**
- **(c) 取消**

**原理**：`today_data.trade_date` 與 `last_analysis.data_basis` 相同 ⇒ 同一份收盤被分析兩次。這會讓 track_record / pnl_ledger 重複計分，勝率與 Brier 全部失真且無法回溯修復。

**典型觸發情境**（都必須攔下）：
- 週六分析過，週一美股開盤前又被要求分析（收盤基準仍是週五，沒有新資料）
- 同一天多次說「分析今日SPX」
- 本機與雲端在同一天各跑一次（**務必先 `git pull`**，否則兩邊帳本分岔且無法合併）

**絕對禁止**：同一個 `report_date` 在任一本帳出現兩筆 entry。

### Step 2 — 回測驗證（報告第一區）

逐項比對上次預測 vs 實際結果：
- ✅ 完全命中：方向+幅度均正確
- 🟡 部分命中：方向正確但幅度不足/過大
- ❌ 未命中：方向錯誤或條件未觸發

計算：
```
命中率 = 完全命中數 / 總預測項目數
方向勝率 = 方向正確數 / 總預測項目數
```

**計分防灌水規則（2026-07-03 起強制）：**
- 「正確未觸發」的單子**不計入完全命中**，另列一類（它證明條件設計對，但不是預測贏）
- 方向判定機械化：實際漲跌 ≥+0.3% 為漲、≤-0.3% 為跌、其間為平。偏多/中性偏多預測遇漲=命中、遇跌=未中、遇平=部分；中性遇平=命中、其餘=部分；偏空同理反向
- **每天必須更新 `{repo}\docs\track_record.json` 累積帳本**：追加一筆 {日期, 拉回機率, 立場, 實際漲跌%, 機械判定}，並重算滾動方向勝率。單日命中率會說故事，累積帳本才看得出系統有沒有 edge
- **Brier score 同步更新（2026-07-07 起強制）**：對前一筆已判定的預測計算 brier=(拉回機率/100 − outcome)²，outcome：跌=1、漲=0、平=排除不計。追加至 track_record.json 的 summary.brier.per_entry 並重算 mean_brier。基準=0.25（永遠報50%的無腦分數），低於 0.25 才代表機率有資訊量
- **報拉回機率的紀律（Brier 啟用後配套）**：有把握時敢報 <35% 或 >75%；沒把握就老實報 50% 附近——**禁止用 55–62 的窄帶數字假裝有觀點**（2026-07-07 首算 mean_brier=0.2535 輸給無腦基準 0.25 的教訓：窄帶躺平+方向錯時代價大）
- **P&L 模擬帳本同步更新（2026-07-07 起強制）**：用今日 OHLC 機械判定上次策略表的成交/出場，追加至 `{repo}\docs\pnl_ledger.json`（規則見該檔 sim_rules：limit/stop/收盤確認三種掛單型態、停損優先、收盤強平1日視野），重算累積 weighted_bp；同時把本次新策略表以 trades_pending 寫入供明日判定。**方向勝率、Brier、P&L 三本帳並列才是系統真實成績單**

偏差分析：未命中的原因（未預期催化劑？指標矛盾？停損是否保護本金？）
若發現系統性錯誤 → 寫入 system_rules（見 Step 6），讓規則累積進化。

### Step 3 — 六維分析（報告第二區）

依以下順序逐一分析，每項都要有明確的多/空/中性判斷：

0. **廣度（Breadth）** — 讀 `today_data.txt` 的 `breadth` 區塊
   - `rsp_spy_ratio`：RSP(等權)/SPY(市值權重)。**升＝中小型股同步參與、指數漲勢紮實；降＝少數權值撐盤、漲勢品質打折**
   - `chg_5d_pct` ≥ +0.5%＝廣度擴張；≤ -0.5%＝廣度窄化
   - **關鍵用法：與指數方向背離時要示警**——指數創高但廣度窄化＝少數股票撐盤，突破可信度下降、拉回機率上調
   - 抓不到時 `breadth` 為 `null`，報告標註「廣度資料缺」，不得憑空推測

1. **價格行為（Price Action）**
   - K線形態（吞沒、錘頭、上吊、射擊之星、十字星等）
   - 成交量與價格的關係（量增價漲＝健康；量縮價漲＝衰竭）
   - 與前高/前低的相對位置、是否創 ATH

2. **均線系統**
   - MA5/MA20/MA50/MA200 多空排列狀態
   - 乖離率：(收盤-均線)/均線 × 100%
   - 黃金交叉/死亡交叉是否已形成或即將形成

3. **技術指標**
   - RSI(14)：<30 超賣，>70 超買，注意頂/底背離
   - MACD：柱狀放大/縮小，多空交叉
   - 布林帶：收盤位置百分比
   - KD：高檔鈍化/超賣反彈

4. **葛蘭威爾八大法則**
   - 買①均線轉升首次穿越 ②跌回均線不破支撐 ③跌破均線迅速拉回 ④乖離過大強彈
   - 賣⑤均線走平頂部穿越 ⑥反彈均線量縮回落 ⑦跌破均線死貓彈失敗 ⑧乖離過大快速修正

5. **纏論（Chan Theory）**
   - 當前筆方向、中樞區間（上沿/下沿）、段結構
   - 頂/底背馳訊號（價格新低但MACD柱收窄=底背馳）

6. **艾略特波浪（Elliott Wave）**
   - 當前波段位置（①②③④⑤ or ABC）
   - 費波回撤位：0.382 / 0.500 / 0.618 / 0.786
   - 推動浪目標：前浪 × 1.618
   - **多情景評估**：列 2–3 個方案並給機率（例：方案A ②浪延伸 55% / 方案B ③浪啟動 30% / 方案C 大修正 15%）

### Step 4 — 拉回機率評分（0–100%）

| 因子 | 權重 | 評分依據 |
|---|---|---|
| 技術指標過熱度 | 25% | RSI>70/布林上軌/KD高檔 |
| 均線乖離率 | 20% | 距MA200乖離>7%為高風險 |
| 利率/匯率/即時事件衝擊 | 30% | **10Y殖利率方向（升=壓股，rate-driven盤最重）+ DXY** + 突發地緣/政策/重大消息的當下不確定性 |
| 成交量衰竭訊號 | 15% | 量縮創高=衰竭 |
| 波浪/纏論結構 | 10% | 第③波末端/頂背馳（**僅作結構參考，不主導評分**）|

> **權重調整（2026-06-23）**：原「波浪/纏論 20%」最主觀、且與「均線乖離」高度重複（同吃 MA/支撐結構）→ 降為 10%；騰出 10% 併入「利率/匯率/即時事件」（升至 30%，反映 2026 年 Warsh 鷹派下的 rate-driven 盤）。**10Y 殖利率方向（升破前高=壓股）由 check_es.py 抓取，是此因子的核心訊號。**
>
> **事件因子的正確用法（回測校準）**：這 30% 主要是「**利率方向 + 即時突發衝擊**」（殖利率飆升、戰事、關稅、突發政策、盤中重大新聞），這類確實放大短線風險，故權重最重。
> 但「**排程事件日曆**」（FOMC/CPI/NFP/OpEx 的已知日期）經 1163 樣本回測證實**幾乎無鑑別力**（事件日 vs 無事件日拉回率僅差約 5pp，通膨日甚至更低）→ **不要因為「今天有 CPI/FOMC」就調高拉回機率**，那是基準率，不是訊號。只有當該事件「實際公布出意外結果」時，才以即時衝擊計入。

**【硬規則・禁止折中】headline 一律等於 elliott 情景權重推導值（rule16），不得再與六因子加權分數平均。**
- 推導式：`跌情景% + 整理情景% × 0.5` ＝ headline
- 六因子表只用來**產生情景權重**，不再對 headline 做第二次平均
- **禁止**寫「情景推導 43.5%、六因子 50.4%、折中報 46%」這種二次平均——那是把數字往中間拉的機制
- 證據（2026-08-13 稽核）：22 筆預測中 **86% 落在 45–62 窄帶、0 筆低於 45**，mean_brier 0.2599 **輸給無腦報 50% 的 0.25**。窄帶來源就是折中
- 有把握就讓推導值帶你到 <40 或 >70；沒把握就老實停在 50，不要用 46/54 假裝有觀點

- <40%：低風險，多頭持續
- 40–60%：中性，謹慎觀察
- 60–80%：中高風險，建議輕倉
- >80%：高風險，嚴控部位

**評分必須遵守 system_rules（見下方），規則優先於主觀判斷。**

### Step 4.5 — Regime 客觀對照（第二視角，必做）

讀取 `today_data.txt` 的 `regime` 區塊，與上面的主觀評分**並列呈現**。這是基於本機 `backtest.py` 1163 樣本回測（VIX/趨勢/MA20 三維），純客觀、與主觀六維獨立，目的是交叉驗證、避免單邊偏誤。

> **【重要・單位不同，禁止直接比大小】**
> 兩者量的不是同一件事：
> - **主觀 headline**＝隔日收盤下跌機率（track_record 以 ±0.3% 收盤漲跌計分）
> - **客觀 regime**＝**未來 5 日盤中低點跌破 -0.75%** 的機率（backtest.py 定義）
>
> 5 日回撤基準率 61.65% 天生就遠高於「隔日收盤下跌」的約 45–50%，所以主觀數字**必然**看起來比客觀低。
> **只比方向與超額（vs_base），不比絕對值**；禁止寫「主觀46 vs 客觀55.4 → 同向」這種直接比大小的句子。

呈現方式（報告與回覆都要列出）：
```
主觀拉回機率：XX%（隔日收盤方向）
客觀 regime 平均：XX%（未來5日盤中回撤，vs 基準 61.65%，超額 ±X.Xpp）
  ├ VIX：{regime} → XX.X%（±X.Xpp）
  ├ 趨勢：{regime} → XX.X%（±X.Xpp）
  └ MA20：{regime} → XX.X%（±X.Xpp）
```

**合併規則（避免確認偏誤）：**
- 主觀與 regime **同向**（都偏多或都偏空）→ 信心提高，可按倉位上限執行
- 主觀與 regime **分歧**（一多一空）→ **倉位減半或等待**，並在報告點明分歧點，不硬幹
- regime 三維內部若彼此分歧（如 VIX 偏空但趨勢偏多）→ 視為中性，以主觀評分為主、保守看待

**重要提醒（regime 的已知限制，引用時要記得）：**
- 歷史 5D 拉回率多在 49–78%，其中 62% 左右是市場「基準率」→ 看的是**超額（vs_base）**，不是絕對值
- 模型鑑別力 AUC：1D=0.66（最準）、3D=0.62、5D=0.61 → **以 1D 為主決策**，5D 當結構參考；事件日曆類因子已證實無效，不採用
- regime 是「結構傾向」不是「明日預測」，仍以白天主觀評分定方向、定倉位
- 數字會漂移：**每季重跑 `{repo}\scripts\backtest.py`** 即可。它會更新 `docs\regime_baseline.json`，而 `fetch_today.py` 每次執行會**自動讀取**該檔，無需手改常數。回測同時輸出 AUC/Brier，可確認 regime 是否仍有鑑別力

### Step 5 — 交易策略表格（報告第三區）

四種策略，每種標明：進場條件、進場價位、**距現價%**、停損、目標①、目標②、風報比、建議倉位：
- 空單優先（最高機率場景）
- 積極空（深度回調場景）
- 等待做多（支撐區接反彈）
- 突破做多（新高繼續追漲）

**【硬規則・rule27 已轉正】進場距離必須錨定當日預期振幅，超標一律不掛：**
- **預期振幅** ＝ 近5日均振幅 與 ATR14 的折中值（兩者取平均）
- **門檻** ＝ 預期振幅 × 0.6。`|進場價 − 現價| / 現價 > 門檻` 的單子 **weight 直接設 0、不寫進策略表**
- **不是標「⚠低成交機率」然後照掛**——那是舊做法，已證實無效
- 證據（2026-08-13 稽核）：累積成交率僅 **19/76 = 25%**，四張單三張接不到，P&L 24 日只有 +2.88bp。8/12 振幅僅 0.36% 而進場位距現價 0.52%，**數學上不可能成交**卻仍掛出
- 寧可只掛 2 張接得到，不要掛 4 張接不到
- 若因此當日無單可掛 → 明確寫「今日無可執行進場位，觀望」，這是正確結果不是失敗

**舊版距現價% 規則（已被 rule27 取代，保留供對照）：**
- 每列策略必算「|進場價−現價|/現價」並填入表格
- **距現價 >0.8% 的單子必須標註「⚠低成交機率」，且不得作為當日唯一主策略**——主策略至少一條要在現價 ±0.8% 內可執行
- 回測時「低成交機率單沒接到」不得當作正常結果帶過，要檢討進場價設計

**掛單型態標註（2026-07-07 新增，供 P&L 模擬帳本機械判定）：**

- 寫入 pnl_ledger.json 的 trades_pending 時明確標註 order 欄位，隔日判定不得模糊

## 三層決策矩陣（兩個確認模式回覆時必須套用）

核心原則：**拉回機率定方向（白天），確認模式只定執行（晚上），不重新分析、不改方向。**

### 第一層：拉回機率 → 今晚劇本與倉位上限
| 拉回機率 | 立場 | 倉位上限 |
|---|---|---|
| <40% | 偏多 | 多單 30% |
| 40–60% | 中性 | 任一方向 ≤20%，區間策略為主 |
| 60–80% | 偏空 | 空單 20%，禁追多 |
| >80% | 強空 | 空單 15%（高波動縮倉）|

### 第二層：期貨確認 → 劇本可信度
跑 `check_es.py`，看 **ES 方向 + NQ(科技領先) + 10Y殖利率 + DXY + macro_backdrop 合成判讀**：

| ES vs 白天立場 | 動作 |
|---|---|
| 同向 | 按劇本，100% 倉位執行 |
| 中性（±0.3%內）| 按劇本，但等開盤確認再進場 |
| 反向 | 倉位砍半，必須等開盤確認 |
| 反向且 >1% | 今晚觀望，先查隔夜新聞（可能有重大消息）|

**宏觀過濾（疊加在 ES 之上）：**
- **10Y 殖利率 +5bps 以上**（UP_RISK_OFF）→ 偏多劇本可信度下調、追多更保守；偏空劇本加分
- **macro_backdrop ≤ -2（RISK_OFF）**→ 即使想做多也降倉、優先等開盤確認；**+2 以上（RISK_ON）**才支持積極做多
- ES 與 10Y 衝突（ES紅但殖利率也飆）→ 視為「漲在刀口上」，不追多

### 第三層：開盤確認 → 進場與否（三項檢查）
| 檢查 | 通過 | 否決 |
|---|---|---|
| 方向 | 首根30分K與劇本同向 | 反向長實體（>0.5%）→觀望 |
| 量能 | `first_30m_vol_ratio` ≥0.9（首30分量/近5日同時段均值，open30_check.txt 直接輸出） | ratio <0.75 = 假動作機率高 |
| 關鍵位 | 價格在劇本進場區附近 | 已跳空越過進場位→不追，等回測 |

三項全過→全倉位按劇本｜過兩項→半倉｜≤一項→今晚不做。

確認模式的回覆必須以明確指令結尾，例如：
「→ 按劇本執行：7,440 進空，停損 7,490，倉位 20%」
「→ ES與劇本衝突：倉位砍半至 10%，等 22:00 開盤確認」
「→ 三項僅過一項：今晚觀望，明天重新分析」

## system_rules：系統規則（會持續累積）

**權威來源＝`{repo}\docs\last_analysis.json` 的 `system_rules` 欄位**（每日沿用+進化），本節只列核心硬規則摘要，兩者不一致時以 JSON 為準。

### 規則分層（2026-08-20 重構，對照表見 `docs\rules_migration_map.md`）

規則膨脹的原因不是條數多，是把三種東西混在同一個欄位。分層後：

| 層 | 位置 | 內容 | 每日讀寫 |
|---|---|---|---|
| **L1 硬規則** | `last_analysis.json` → `system_rules` | 一行常則正文，**嚴禁寫入當日數值快照** | ✅ |
| **L2 候補** | `last_analysis.json` → `rule_candidates` | 單行命題 ＋ **結案條件**（n 樣本或到期日） | ✅ |
| **當日狀態** | `last_analysis.json` → `rule_status` | 今天哪幾條觸發／不適用，每日重寫 | ✅（寫） |
| **L3 教訓** | `docs\lessons.md` | 案例敘事、演進史、證偽紀錄、已歸檔規則 | ❌ |
| **待實作** | `docs\rules_todo.json` | 工程項目（非待驗證假設），不佔候補名額 | ❌ |

**三條維護紀律（違反即造成 2026-08-20 之前的膨脹）：**
1. **規則正文不得混入當日數值**——「（現 VIX 14.89…）」這類快照隔天就過期卻被複製到永遠，一律寫進 `rule_status`
2. **新增候補必須同時寫結案條件**——沒有「幾個樣本後判生死」的候補會永遠掛著（rule18／rule22 曾掛超過一個月、零樣本）
3. **案例敘事寫 `lessons.md`，不寫規則正文**——規則是「該怎麼做」，案例是「為什麼」，後者不需要每天讀

核心硬規則（2026-07-03 大掃除後版本）：
1. MACD柱 <-15 且「利率/匯率/即時事件」因子評分 ≥70 → 評級不得高於中性，禁止突破做多（舊版引用已廢止的「地緣因子/20」，已改錨定六因子表）
2. 脆弱停火/主動軍事威脅存在時 → 「利率/匯率/即時事件」因子評分下限 75
3. 突破做多必要條件（缺一不可）：突破均線 + **帶量** + MACD柱收窄。**量能判定：當日只用「相對量」（初值 vs 近5日初值均值，>1.1 倍為帶量），禁止用初值卡 4B 絕對門檻**——初值常被大幅上修（6/30 初值 3.76B 判量縮、復核 6.04B 實為帶量真突破），絕對量結論待隔日 rule6 復核蓋章
4. rule8【硬】回踩做多錨定支撐位本身、站穩即進、禁掛深；且**不掛限價單在支撐等接**（支撐常先假破再站回，掛單會被掃）
5. rule12 破底空必須「收盤確認」，不看盤中插針
6. rule15 類股與指數嚴重背離時（如半導體崩但 SPX 平），對重倉該類股者以類股訊號（SOXX/NQ）為準

每次回測若發現新的系統性錯誤 → 新增規則寫入 last_analysis.json 的 `rule_candidates`（**必附結案條件**），並同步更新本節。候補經實戰驗證後轉正至 `system_rules`；被證偽的規則連同證偽經過一起寫入 `docs\lessons.md` 歸檔，不佔用活動清單。

> ⚠️ **本節摘要與 JSON 目前有兩處已知不一致**（2026-08-20 發現，未擅自處置，見 `lessons.md` 第五節）：
> 摘要第 3 條寫「MACD柱**收窄**」而 JSON 寫「MACD柱正且**放大**」；摘要第 4 條多了「不掛限價單在支撐等接」而 JSON 無此禁令。
> 依本節開頭規定，**執行時一律以 JSON 為準**；兩處分歧需另案決定。

## 快速確認模式（不產 HTML、不推 GitHub、純文字回覆）

### 模式一：期貨確認（觸發詞：「SPX期貨確認」「ES確認」「ES怎樣」）

1. 執行 `{repo}\scripts\check_es.py` → Read 同資料夾 `es_check.txt`
2. 判斷標準：
   - ES ≥ +0.3% → 偏多開盤；ES ≤ -0.3% → 偏空開盤；之間 → 中性
   - **同時看 10Y 殖利率（±5bps）、DXY、NQ 強弱、SOXX 半導體、macro_backdrop 合成分**
   - **先看 `session` 時段標示**：ASIA_THIN（台灣白天）＝亞洲薄盤，反轉率高、僅供參考，**不可據此執行**，21:00 後必須複查；US_PREOPEN/REGULAR 才是可執行讀數
   - **SOXX 半導體（rule15）**：對重倉半導體者比 NQ 更準；美盤時段看 `semi_vs_spx` 背離值，≤-1.0pp＝輪動殺半導體警報（注意：亞洲時段 SOXX 為前日收盤資料）
   - `implied_spx_open` 為隱含現貨開盤近似值，直接對照關鍵價位表
3. 對照 last_analysis.json 的評級，輸出簡短結論（6行以內），必含宏觀層：
   ```
   ES期貨：-0.87%（偏空）｜NQ：-1.39%（科技領跌）
   10Y：4.51%（+5.8bps 壓股）｜DXY：持平｜VIX：19.8
   盤前合成：RISK_OFF 偏空（-3）
   與今日分析（中性偏空54%）方向一致 ✅
   → 按計畫：反彈7,468做空 / 跌破收盤確認加空
   ```
4. **方向一致** → 提示按策略執行；**方向相反** → 縮倉觀望、等開盤確認；**殖利率飆+backdrop轉空** → 即使ES紅也不追多

### 模式二：開盤確認（觸發詞：「SPX開盤確認」「SPX開盤怎樣」）

⚠️ 需在台灣時間 22:00 後執行（第一根30分K收完）。

1. 執行 `{repo}\scripts\check_open30.py` → Read 同資料夾 `open30_check.txt`
2. 判斷第一根 30分K：
   - 方向（UP/DOWN）+ 收盤位置 vs 開盤
   - 量能：直接用輸出的 `first_30m_vol_ratio`（首30分量 vs 近5日同時段均值）——≥1.2 放量、<0.75 量不足假動作風險，不再憑感覺
   - **類股同步（rule15）**：看 `sector_sync`（Nasdaq + SOXX 半導體首30分）與 `sync_read`——**SPX 綠燈但半導體背離＝對重倉半導體者是無效綠燈，一律降級觀望**
   - 是否觸及 last_analysis.json 的關鍵位
3. 輸出簡短決策（5行以內）：
   ```
   開盤30分：7,438→7,457（UP）｜量2.1億｜高7,483觸MA20後回落
   與分析方向【一致/不一致】
   → 建議：【按策略進場 XXX / 縮倉觀望，等下一根K確認】
   ```
4. 決策規則（**五條紅線**，每次開盤確認都要對照）：
   - **✅ 可進場**：30分K方向與分析一致 + 量能正常 + 站穩劇本進場區 → 按策略進
   - **🟡 應觀望**：方向不一致、或在關鍵區間中段遊走、量能不足（<1.5億）→ 縮倉50%或不做
   - **🚫 不能追**：開盤跳空已越過進場位（追高/殺低）→ 不追，等回測關鍵位
   - **🛑 跌破停損**：觸及 last_analysis.json 停損位 → 直接砍/翻向，不凹單
   - **⚠️ 只是反彈別加碼**：無量反彈、NQ 不同步、未收復關鍵位 → 視為逃命彈，不加碼

### 模式三：睡前檢查（觸發詞：「SPX睡前檢查」「SPX睡前確認」）

⚠️ 台灣時間 22:30–23:00 執行（開盤約一小時後），是用戶睡前的**最終過夜閘門**——用戶凌晨收盤時在睡覺，此後只剩預掛單。

1. 執行 `check_open30.py`（看開盤至今走勢+類股同步）與 `check_es.py`（最新宏觀層）→ Read 兩個 txt
2. 對照 last_analysis.json 的關鍵位與策略，輸出**過夜決策**（8行以內）：
   - 現價位置 vs 關鍵支撐/壓力（守住哪條、破了哪條）
   - 類股同步狀態（半導體/NQ 有無背離——對重倉半導體的用戶最關鍵）
   - **明確指令收尾**：「留倉，停損掛 X,XXX」／「減碼 X 成再睡」／「2倍/高beta出清，核心停損掛 X,XXX」
3. 原則：跳空風險靠**部位大小**控管而非停損價（睡覺時段停損擋不住跳空）；有隔夜重大事件（rule4 清單）時預設偏保守

## 技術注意事項

- **一天只能一邊跑（本機 or 雲端），且開始前必先 `git pull`**——三本帳逐日累加，分岔後無法合併。以 Step 1.5 的 `check_duplicate.py` 作機械攔截，不依賴記憶
- **雲端資料架構（2026-08-13 定案）**：GitHub Actions（`.github/workflows/fetch-data.yml`）每個交易日 21:15 UTC（台北 05:15）自動抓 Yahoo 並 commit 到 `data/`。雲端 session 抓不到 Yahoo 時，`fetch_today.py`／`check_es.py` 會**自動退回讀 `data/` 快照**並在輸出標明 `SNAPSHOT`。判讀規則：快照對**每日完整分析**可用（時點=收盤後）；對**期貨確認／開盤確認／睡前檢查**過舊不可用——雲端遇 SNAPSHOT 標記時，快速確認模式一律回覆「雲端無即時資料，請在本機執行」
- **雲端／MITM proxy 環境抓不到資料時**：yfinance 走 curl_cffi 做 TLS 指紋偽裝，會被解密型 proxy reset（錯誤：`curl: (35) Recv failure: Connection reset by peer`）。`scripts/yf_compat.py` 會自動退回 plain requests 重試；若仍失敗，在雲端環境變數設 **`SPX_HTTP_PLAIN=1`** 強制從一開始就用 requests。**注意：純 requests 較容易被 Yahoo rate limit，故本機不要設**
- **`check_es.py` / `check_open30.py` 必須看 `data_status` 欄位**：`OK`＝可信；`PARTIAL`＝部分指標缺失，合成分不可信、須在報告標註；`ALL_FAILED`＝核心指標全掛，**此時不會有 `macro_backdrop`**，禁止把「缺資料」讀成「市場中性」（2026-08-13 雲端實測：五指標全 rate-limited 仍寫出 score 0／MIXED 中性的假訊號）
- **一律用 `python3` 執行腳本，禁止用 `python`**——本機 `python` 可能指向無 yfinance 的 venv（hermes-agent），只有 `python3`（pythoncore-3.14）裝了 yfinance；雲端 Linux 環境同樣以 `python3` 為準，是跨環境唯一安全解
- **禁止把腳本呼叫接 `| tail` / `| head`**——管線會吃掉非零 exit code，抓取失敗時指令鏈不會中斷，會讀到前一天的舊 txt 卻誤以為是今天的。改用 `python3 x.py; echo "exit=$?"`，並**每次核對輸出的 `trade_date` 是否為預期交易日**（2026-08-12 發現：`python` 解析到錯誤 venv 導致 fetch 靜默失敗）
- **禁止 print 中文**到 subprocess stdout（Windows cp950 亂碼）→ 寫 .txt 後用 Read 讀
- yfinance 回傳 DataFrame 可能是 MultiIndex columns → 需 squeeze() 或攤平
- PowerShell 不支援 `&&` → 用分號 `;`
- 若 yfinance 抓到的最新日期早於今天 → 說明美股尚未收盤/休市，標注數據基準日

## 市場筆記標準輸出格式

每次完成分析後，在報告最末尾輸出以下固定格式區塊（關鍵字不可更動）：

```
📋 市場筆記速記（可直接貼入 App）

日期：YYYY-MM-DD
收盤：X,XXX（+X.XX%）
VIX：XX.XX
拉回機率：XX%

纏論中樞：X,XXX – X,XXX
關鍵支撐：X,XXX / X,XXX / X,XXX
關鍵阻力：X,XXX / X,XXX / X,XXX

今日催化劑：（一行簡述）
明日觀察：（一行簡述）

策略摘要：
空單：進場 X,XXX｜停損 X,XXX｜目標① X,XXX｜目標② X,XXX
做多：進場 X,XXX｜停損 X,XXX｜目標① X,XXX｜目標② X,XXX

📌 回測參照（下次勿刪）：
拉回機率 XX%｜支撐 X,XXX / X,XXX｜阻力 X,XXX / X,XXX｜纏論上沿 X,XXX
```

解析說明（給 App 的 MarketNotes.jsx）：
- 「收盤：」後面的數字 → spxClose（取後面第一個數字，忽略括號）
- 「VIX：」後面的數字 → vix
- 「拉回機率：」後面的數字 → pullbackProb（取數字，去掉 %）
- 「纏論中樞：」後面的範圍 → chanZhongShu（取「X,XXX – X,XXX」格式）
- 「關鍵支撐：」後面的數字列表 → support（取「/」分隔的數字列表）
- 「關鍵阻力：」後面的數字列表 → resistance（取「/」分隔的數字列表）
- 「今日催化劑：」後面的文字 → catalyst（取冒號後整行文字）
- 「明日觀察：」後面的文字 → nextDayWatch（取冒號後整行文字）
- 「📌 回測參照」這行 → 整行儲存為 backtestRef，並存入 localStorage key: 'lastBacktestRef'
